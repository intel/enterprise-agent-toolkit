# Known errors in this repository's docs

These pages in `docs/` and `README.md` disagree with the code. When a user follows one of them and it fails, tell them which line is wrong and use the correct version below. Remove an entry here when its page is fixed.

## Written for the release track

The pages were written for Toolkit Manager `release-1.2`. On the main track:

| Page | Says | On the main track |
|---|---|---|
| `docs/README.md`, `docs/single-node-deployment.md` (quick start) | `git clone -b release-1.2 ...` | Plain `git clone` (the default branch is main). `README.md` already does this, so the two disagree. |
| `docs/single-node-deployment.md`, `docs/configuring-inference-config-cfg-file.md` | `auth_provider: "litellm"` in `global_config.yaml`, "set by init agent-toolkit" | `init` seeds `auth_type: "litellm_vkey"` in `config.agent-toolkit.yaml`. A leftover `auth_provider` must agree with it, or preflight stops. |
| `docs/single-node-deployment.md` "Access the LiteLLM UI" | `https://litellm.<domain>/ui`, user `admin`, password = master key | `https://litellm-ui.<domain>/ui/` (path mode `https://<domain>/litellm/ui/`), Keycloak sign-in (`platform-admin`) |
| `docs/validate-stack.md` | The node preflight runs at the start of `install` and writes `health-report-latest.*` | `install` does not run it. Run `playbooks/preflight-check.yml` by hand (agent-toolkit-install skill, step 5). |
| `config.yaml` comments above `auth_type` and `node_preflight_enabled` | "This release reads auth_provider in global_config.yaml instead"; node checks "at the start of install" | `auth_type` is the switch on the main track, and the node checks do not run at install |
| `config.yaml` comment above `keycloak_agent_realm` | "Optional in LiteLLM mode: set keycloak_enabled: true for the realm" | Keycloak is installed by default, and the realm is created by default |

## Wrong on both tracks

| Page | Says | Correct |
|---|---|---|
| `docs/prerequisites.md` hardware table | RAM minimum 32 GB, recommended 64 GB | The default install requests about 131 GiB (default model 96 GiB plus guard model 16 GiB plus the stack). With 128 GB use `qwen2-5-coder-7b` (agent-toolkit-install skill). |
| `docs/agent-sandbox.md` (overview and in-cluster section) | Client pods "need no RBAC"; "the router handles all Kubernetes API calls" | The SDK creates SandboxClaims with the caller's credentials. An agent pod needs a Role in `agent-sandbox-system` (agent-toolkit-components skill, `references/sandbox.md`). |
| `docs/agent-sandbox.md` | The Kata warm pool is created "without a readiness gate" | The install waits for every pod in `agent-sandbox-system`, Kata pods included |
| `docs/agent-sandbox.md` | `kubectl get sandboxwarmpool`: "Expected: SIZE=5 and READY=5" | v0.5.0 shows only `NAME READY AGE` |
| `docs/agent-sandbox.md` (logs) | `kubectl logs -n agent-sandbox-system -l app.kubernetes.io/name=agent-sandbox` | `kubectl logs -n agent-sandbox-system deploy/agent-sandbox-controller` |
| `docs/agent-sandbox.md` | Kata chart values in `core/helm-charts/kata-deploy/values.yaml` | Kata is installed by Toolkit Manager (`<root>/roles/kata_containers/`) |
| `charts/agent-sandbox/kata-templates.yaml` comment | `client.create_sandbox(template="kata-sandbox-template", ...)` | `client.create_sandbox(warmpool="kata-pool", namespace="agent-sandbox-system")` |
