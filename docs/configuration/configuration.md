# Configuration

[← Docs index](../README.md)

After `init`, configuration lives as several YAML files under `env/<name>/` (the default name is `local`). You edit those files, then run `install`. There is no single INI file. Secrets (Redis password, gateway keys, and so on) are generated by the installer; do not put them in git.

```bash
./stack-manager init agent-toolkit --env <env>
```

Omit `--env` to use `local`.

> Older docs and the standalone monolith used `core/inventory/agentic-config.cfg` and `vault.yml`. Those files are gone. The mapping at the bottom of this page is only for people migrating from that layout.

## The files

These are the files `init` writes under `env/local/`. Change the copies here; they are what `install` reads.

| File | What it is for |
|---|---|
| `global_config.yaml` | Cluster-wide: domain, TLS, auth, storage, proxy, bring-your-own kubeconfig |
| `config.inference.yaml` | Turn model serving (and optional routers) on |
| `models.yaml` | Catalog. `autodeploy: true` starts that model |
| `config.agent-toolkit.yaml` | Toolkit knobs: namespaces, optional KubeRay, MCP list |
| `inventory/hosts.yaml` | Which nodes are in the cluster |

### `global_config.yaml`

```yaml
auth_provider: litellm           # litellm | keycloak
base_domain_name: api.example.com
gateway_tls_mode: selfsigned     # selfsigned | custom
# gateway_tls_mode: custom
# gateway_tls_cert_file: /path/to/cert.pem
# gateway_tls_key_file: /path/to/key.pem
# existing_kubernetes: /path/to/kubeconfig   # omit to let the installer create Kubernetes
storage_backend: local-path      # local-path | nfs | ceph
# http_proxy: http://proxy.corporate.com:8080
# https_proxy: http://proxy.corporate.com:8080
# no_proxy: localhost,127.0.0.1,.svc,.cluster.local
```

| Setting | Effect |
|---|---|
| `auth_provider` | `litellm`: LiteLLM gateway, Langfuse traces, and the content-safety guardrail. `keycloak`: Keycloak in front of the AI gateway. |
| `base_domain_name` | Public hostname of the API. Must match DNS/`/etc/hosts` and the certificate. |
| `gateway_tls_mode` | `selfsigned` for a lab. `custom` plus cert/key paths for the cert from [Prerequisites](../getting-started/prerequisites.md). |
| `existing_kubernetes` | Path to a kubeconfig if the cluster already exists. Omit to provision Kubernetes. |
| `storage_backend` | Where PVCs go. `local-path` on one node; `nfs` or `ceph` on several. |
| `http_proxy` / `https_proxy` / `no_proxy` | [Corporate proxy](../deployment/proxy.md). `no_proxy` must include `.svc` and `.cluster.local`. |

### `config.inference.yaml`

```yaml
llm_services_deploy_models: true
# hybrid_router_enabled: false
# vllm_sr_enabled: false
```

`llm_services_deploy_models: true` is what actually starts model pods. Which models start is decided in `models.yaml` (`autodeploy: true` on each entry). Routing is opt-in; see [Routing](routing.md) and [Hybrid router](hybrid-router.md).

### `models.yaml`

```yaml
  - name: qwen3-4b
    model_id: Qwen/Qwen3-4B-Instruct-2507
    category: llm
    autodeploy: true
```

The catalog names, Hugging Face ids, and sizing notes are in the [single-node quickstart](../getting-started/quickstart.md#3-choose-a-model).

### `config.agent-toolkit.yaml`

```yaml
# redis_stack, pgvector, agent_sandbox, mcp_servers, keycloak_agent_config install with the layer
kuberay_enabled: false
```

| Setting | Default | Meaning |
|---|---|---|
| `redis_stack_namespace` | `redis` | Namespace for Redis Stack |
| `pgvector_namespace` | `pgvector` | Namespace for PostgreSQL + pgvector |
| `pgvector_database` / `pgvector_username` | `agentdb` / `agentuser` | Database and role |
| `agent_sandbox_namespace` | `agent-sandbox-system` | Sandbox operator and pods |
| `mcp_servers_namespace` | `mcp` | Namespace for MCP servers |
| `mcp_servers_list` | empty | No MCP servers until you add entries |
| `kuberay_enabled` | `false` | Set `true` to install Ray. [KubeRay](../reference/kuberay.md) |
| `redis_stack_enabled` / `pgvector_enabled` / `agent_sandbox_enabled` / `mcp_servers_enabled` | `true` | Set `false` to skip that component |
| `keycloak_agent_config_enabled` | follows `keycloak_enabled` (`true`) | Creates the `agent-toolkit` realm on the platform Keycloak |
| `keycloak_agent_realm` / `keycloak_agent_client_id` | `agent-toolkit` / `agent-toolkit-client` | Realm and OIDC client names |

Source defaults (copied at `init`): `config.yaml` at the root of this repo.

## Hugging Face token

The Hugging Face token is not stored in YAML. Export it in the same shell that runs `install`:

```bash
export HF_TOKEN=hf_...
```

Skip this if you are not serving gated models (Llama, Gemma), or if `llm_services_deploy_models` is `false`. Qwen3-4B is ungated.

## If you used the old INI file

The standalone stack stored flags in `agentic-config.cfg`. Stack Manager maps those flags to the YAML files above. Use this table only if you are migrating; new installs should ignore the left column.

| Old `agentic-config.cfg` | Now |
|---|---|
| `deploy_redis` / `deploy_pgvector` / `deploy_agent_sandbox` | Installed with the toolkit |
| `deploy_kuberay=on` | `kuberay_enabled: true` |
| `deploy_llm_models=on` + `models=...` | `llm_services_deploy_models: true` + `autodeploy: true` per model |
| `deploy_guardrails=on` | `auth_provider: litellm` |
| `deploy_observability=on` | Langfuse comes with `auth_provider: litellm` |
| `cert_file` / `key_file` | `gateway_tls_mode: custom` + cert/key paths |
| `cluster_url` | `base_domain_name` |
| `hugging_face_token` | `export HF_TOKEN=...` |
| `http_proxy` / `https_proxy` / `no_proxy` | Same keys in `global_config.yaml` |
| `deploy_kubernetes_fresh` / ingress / gateway | Installed by Stack Manager; BYO cluster = `existing_kubernetes` |
| `vault.yml` | Removed: installer generates secrets |

`deploy_vllm_sr`, `rack_scale_mode`, and some hybrid paths were still backlog in the first Stack Manager release.

## Next steps

After you change YAML, re-run `./stack-manager install agent-toolkit`. Toolkit components that are already installed (Redis, pgvector, sandbox, KubeRay) are skipped on a re-run, so their settings only apply to a fresh install: see [Decommission and redeploy](../deployment/decommission.md). The [single-node quickstart](../getting-started/quickstart.md) shows a first working set of values. In-cluster URLs for Redis, pgvector, and the sandbox are in the [backend connection reference](../reference/backend-connections.md). Content-safety screening is covered in [Guardrails](guardrails.md). Virtual model names are covered in [Routing](routing.md). If install fails, see [Troubleshooting](../faq-and-troubleshooting/troubleshooting.md).
